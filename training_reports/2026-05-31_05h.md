## IST Scholar — Papers EIC Encontrados

### Paper 1

**Título:** INESC-ID @ eRisk 2025: Exploring Fine-Tuned, Similarity-Based, and Prompt-Based Approaches to Depression Symptom Identification

**Autores:** Diogo A.P. Nunes, Eugénio Ribeiro

**Afiliações:** INESC-ID Lisboa + Instituto Superior Técnico, Universidade de Lisboa + ISCTE-IUL, Lisboa

**Ano:** 2025 (publicado arXiv em 3 de Junho de 2025)

**DOI/URL:** https://arxiv.org/abs/2506.02924

**Resumo:** O trabalho descreve a abordagem da equipa ao eRisk 2025 Task 1: Search for Symptoms of Depression. Dado um conjunto de frases e o questionário BDI (Beck's Depression Inventory-II), os participantes submeteram até 1.000 frases por sintoma de depressão ordenadas por relevância. As submissões foram avaliadas segundo métricas de Information Retrieval (AP, R-PREC). Os autores exploraram fine-tuning de foundation models, similaridade semântica de frases, LLM prompting e técnicas de ensemble.

**Metodologia principal:**
- Fine-tuning de modelos de linguagem (foundation models) para classificação de relevância
- Embedding-based sentence similarity para ranking semântico
- Prompt engineering sobre LLMs (GPT / open-source models)
- Ensemble de múltiplas abordagens para maximizar AP e R-PREC

**Resultados chave:**
- Sistema competitivo em eRisk 2025 Task 1 — identificação de sintomas BDI-II
- Ensemble combinando os três paradigmas (fine-tuned + similarity + prompt) superou abordagens individuais
- Métricas IR (Average Precision) usadas como ground truth standard

**Contribuição para o estado da arte:**
Demonstra que combinar fine-tuning, similaridade semântica e LLM prompting em ensemble é mais robusto do que qualquer abordagem isolada para tarefas de IR clínico em português/inglês — contribuição relevante para NLP aplicado à saúde.

**Padrões extraídos para o Doctor:**
- Estrutura: Introduction → Task Description → System Architecture → Experimental Setup → Results → Conclusion (padrão IberSPEECH / ACL workshops)
- Terminologia técnica IST em uso: *foundation model fine-tuning*, *sentence similarity*, *ensemble techniques*, *information retrieval metrics*, *relevance ranking*
- Citação de métricas standard IR (AP, R-PREC) como KPI — prática IST/INESC-ID
- Autores IST declaram afiliação dupla: INESC-ID Lisboa + IST (Universidade de Lisboa)
- Referências em formato IEEE/ACL com venue abreviado (eRisk 2025, IberSPEECH)

### Paper 2

**Título:** Accelerat.AI: INESC-ID/IST-Universidade de Lisboa Contributions Towards Improved Conversational Agents in European Portuguese

**Autores:** Alberto Abad, Sérgio Paulo, Rubén Solera-Ureña, Anna Pompili

**Afiliações:** INESC-ID + Instituto Superior Técnico, Universidade de Lisboa

**Ano:** 2024

**DOI/URL:** https://www.isca-archive.org/iberspeech_2024/abad24b_iberspeech.html — DOI: 10.21437/IberSPEECH.2024-61

**Venue:** IberSPEECH 2024, pp. 293–296

**Resumo:** O projecto Accelerat.AI visa criar soluções disruptivas baseadas em agentes de IA Conversacional (CCaaS — Contact Center as a Service) para acelerar a interacção entre entidades públicas/privadas e clientes/cidadãos. O objectivo é construir uma plataforma de assistentes conversacionais modulares para línguas fora do roadmap dos 5 maiores tech companies, começando pelo Português Europeu. Prevê-se resolução de ~80% dos casos de suporte com disponibilidade 24/7.

**Metodologia principal:**
- Arquitectura modular de assistentes conversacionais para Português Europeu
- ASR (Automatic Speech Recognition) adaptado ao PE
- NLU/NLG pipelines especializados por domínio/indústria
- Integração CCaaS com entidades públicas e privadas portuguesas

**Resultados chave:**
- Plataforma inclusiva para língua portuguesa fora do top-15 dos grandes fornecedores tech
- Parceria com Defined.AI, INESC-ID e IST como núcleo técnico

**Contribuição para o estado da arte:**
Primeiro projecto de escala nacional português focado em Conversational AI para PE com arquitectura CCaaS modular — preenche lacuna de recursos NLP para línguas low-resource europeias fora do ecossistema dos grandes fornecedores (Google, Microsoft, Amazon).

## Cross-training Insights

### 1. HACKER → DOCTOR: Segurança na Geração de Documentos

Ao gerar relatórios académicos com `python-docx` ou `reportlab`, o Doctor deve:
- Nunca incorporar paths de ficheiro não sanitizados em templates DOCX (path traversal em `docxtpl`)
- Validar metadados de citações antes de os injectar em LaTeX (LaTeX injection via `\input{}` malicioso)
- Usar `pip-audit` no ambiente de geração de documentos para garantir dependências sem CVEs
- Se o Doctor consumir APIs externas para citações, sanitizar respostas antes de as incorporar em documentos

### 2. RIDER → DOCTOR: Gestão de Estado do Projecto de Dissertação

O Doctor pode adoptar o padrão DAG do Rider para estruturar dissertações longas:
- **DAG de dissertação:** Proposta → Revisão Literatura → Metodologia → Implementação → Avaliação → Conclusão
- Cada nó tem inputs/outputs definidos — evita retrabalho e garante rastreabilidade
- LangGraph checkpointing aplicado à escrita: guardar estado em cada capítulo completado
- Estado persistente = histórico de versões de cada secção, recuperável após falha

### 3. DOCTOR → RIDER: Rigor Académico nos Relatórios de Orquestração

Os relatórios de execução do Rider devem adoptar padrões IST:
- Estrutura formal: Objectivo → Metodologia → Resultados → Análise → Conclusão
- Métricas quantitativas obrigatórias (latência, throughput, erro rate) — não apenas texto descritivo
- Referências a trabalho relacionado (outros frameworks) com citação IEEE quando relevante
- Tabelas de comparação em vez de prosa para resultados de benchmark

### 4. IST Scholar → DOCTOR: Padrões de Escrita Verificados em Trabalhos EIC IST Reais

A partir dos dois papers IST/INESC-ID encontrados, o Doctor aprende:
- **Títulos IST** seguem o padrão: `[Sistema/Projecto]: [Instituição] [contributions/approaches] to [Problema]`
- **Abstract** IST (4-6 frases): contextualização → tarefa → metodologia → resultados → impacto
- **Afiliação dupla** é norma: INESC-ID + IST declarados explicitamente
- **Métricas de avaliação** standard: AP, R-PREC para IR; BLEU/ROUGE para NLG; accuracy/F1 para classificação
- **Ensemble** é metodologia favorita em papers aplicados IST (combina múltiplos paradigmas)
- Papers curtos IST (4 pp.) em conferências focam-se em contribuição técnica directa sem revisão extensa da literatura
