#### Padrão 1 — Docling: Extracção estrutural antes de edição

```python
# Antes de editar qualquer documento, extrair estrutura com Docling
from docling.document_converter import DocumentConverter

def load_document_structure(path: str) -> dict:
    converter = DocumentConverter()
    result = converter.convert(path)
    doc = result.document
    return {
        "sections": [item for item in doc.items if item.label == "section_header"],
        "tables": doc.tables,
        "figures": doc.pictures,
        "text_blocks": [item for item in doc.items if item.label == "text"],
        "export_markdown": doc.export_to_markdown(),
        "export_json": doc.export_to_dict(),
    }
```

**Por quê**: Ao editar documentos .docx existentes, o Doctor opera actualmente sobre o XML python-docx directamente, o que é frágil para documentos formatados manualmente. Docling fornece uma representação semântica (secções, tabelas, figuras) com posição e hierarquia, permitindo edições cirúrgicas sem corromper a formatação.

#### Padrão 2 — NOVAthesis: Template parametrizado para IST Lisboa

```latex
% Parâmetros essenciais para dissertação IST Lisboa
\documentclass[
  doctype=mscplan,        % mscplan | msc | phd | bsc
  school=ist/ul,          % Instituto Superior Técnico, Universidade de Lisboa
  lang=pt,                % Língua principal: pt | en
  fontstyle=kpfonts,      % Família de fontes
  coverlang=pt,           % Capa em português
  biblatex/style=numeric, % Estilo de citação IEEE-like
  biblatex/sorting=nyt
]{novathesis}

% Metadados obrigatórios
\thesistitle{Título da Dissertação}
\thesissubtitle{Subtítulo (opcional)}
\thedegree{Mestrado em Engenharia Informática}
\theauthor{Nome do Autor}
\themonth{Maio}\theyear{2026}
\theadvisers{Prof. Nome Orientador (IST)}
```

**Por quê**: O Doctor recebe pedidos de dissertações IST Lisboa com frequência. Conhecer a classe `novathesis` com os parâmetros correctos para `school=ist/ul` permite gerar templates LaTeX conformes sem o utilizador ter de ajustar manualmente a classe. A estrutura de capítulos (Introdução, Estado da Arte, Implementação, Avaliação, Conclusão) é gerada automaticamente pela classe.

#### Padrão 3 — Quarto: Pipeline de publicação com código reproduzível

# _quarto.yml — configuração de projecto académico
project:
  type: book

  title: "Título do Trabalho"
  author: "Nome do Autor"
  date: today
  chapters:
    - index.qmd          # Introdução
    - estado_arte.qmd    # Estado da Arte
    - metodologia.qmd    # Metodologia
    - resultados.qmd     # Resultados
    - conclusao.qmd      # Conclusão
    - references.qmd     # Referências

    include-in-header: preamble.tex

    theme: cosmo

O `.qmd` permite misturar prosa académica com código Python executável (resultados de experiências inline), e exportar simultaneamente para PDF (submissão), DOCX (revisão com track changes pelo orientador) e HTML (publicação web) a partir de uma única fonte.
